# Runtime 与 LOD

平台使用固定版本及参数的确定性工具，从已确认的质量母版派生 runtime，包括所需的 meshopt 几何压缩和 KTX2 贴图处理。作者只需交付母版及依赖，**不要求自行交付 runtime、压缩件或多 LOD 文件**。可自愿附手工远景剪影提示，是否采用由平台决定。

## 输出结构与一致性

单个资产的 runtime 使用 **一个 GLB**，同一父节点下提供 `<name>_LOD0`、`<name>_LOD1`、`<name>_LOD2`。消费端每次仅显示一个等级，负责阈值、隐藏和切换；母版不内置 LOD 切换逻辑。

跨等级保持同一原点、标称尺寸、前向、材质槽与资产语义。需要动作时，还须保持契约要求的节点、枢轴和动作一致性。屏幕阈值由真实消费场景实测确定，文档不提供未经验证的通用切换值。

## 三角面目标

以下为平台 runtime 目标，不是母版减面要求，也不自动构成工具已实现或性能已达标的证明。

| 档位 | LOD0 三角面目标 | 其他等级 |
| --- | ---: | --- |
| 主体 | 3,000–15,000 | 按消费场景确定 |
| 中型 | 500–5,000 | 按消费场景确定 |
| 重复件 | 12–300 | 按消费场景确定 |
| ISO 集装箱 | ≤1,000 | LOD1 约 100；LOD2 为 12 |

ISO 各级保持确认的标称尺寸和共享中性材质。不得通过拆成多个资产、改标签或减少母版质量来绕过预算。最终实例数量、draw calls、内存、帧时和画面结果由消费者在固定场景中验收。

## 能力边界与出处

当前静态派生适用范围为静态刚体，不覆盖动画、蒙皮、morph、instancing 或压缩母版。动态资产须另行确认保真派生支持；不通过压平动作或要求作者自制 runtime 绕过能力缺口。

单 GLB 的层级组织不保证任意播放器自动切换 LOD。所选 LOD 扩展、meshopt/KTX2 解码及场景组合必须在固定版本消费者中验证，不能把几何派生成功写成动画或跨引擎兼容已通过。

派生保留母版原字节。记录母版 SHA-256、runtime SHA-256、派生工具版本/参数及派生回执 SHA-256。runtime 沿用相应母版的资产 `id@version`；相同字节复用，重新派生导致字节变化时使用新的资产版本，不覆盖已发布版本。母版 SHA 与 runtime SHA 互不替代。

完成确定性预检后可进入已授权的静态草稿流程；正式 active 仍以消费者对确切版本和场景的验收为准。预检/暂存本身不生成 LOD。
